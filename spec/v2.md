# AgentWharf Hub Protocol v2

## Status

This is the current protocol specification. It inherits v1 only where this
document does not version a rule differently. The generic Hub remains
host-neutral: platform extensions are opaque types and payloads.

## Negotiation

- A peer that negotiates `protocol_version: 2` receives v2 rules only.
- A peer that negotiates v1 receives only frozen legacy rules from `v1.md`.
- One logical publisher warning maps to exactly one event type per connection.
  Dual emission is forbidden.

## Historical Pagination

`history.page` is a v2-only, capability-gated explicit client read. It is not
reconnect replay, live delivery, or a request to replay an entire Task. The Hub
accepts and returns one authorized `session_id`; deployments join Task/Run
references outside this protocol, and a multi-Run Task pages each referenced
Session separately.

Only a v2 `hello.ack` that includes
`capabilities.history_page: { "max_limit": 100 }` permits the frame. A v1
acknowledgement omits the capability and a v1 `history.page` frame receives
`error(code=history_unsupported)` without changing live subscription, replay
cursor, or durable state.

```json
{
  "frame": "hello.ack",
  "protocol_version": 2,
  "sessions": [],
  "capabilities": {
    "history_page": { "max_limit": 100 },
    "attention_summary": { "max_sessions": 64 }
  }
}
```

```json
{
  "frame": "history.page",
  "request_id": "hist_01H8X",
  "session_id": "ses_01H8X",
  "before_seq": 58,
  "limit": 100
}
```

Rules:

1. `before_seq` is an exclusive cursor. When omitted, the Hub captures the
   current latest durable sequence in the read snapshot and returns the newest
   page. When supplied, it returns only events with `seq < before_seq`.
2. `limit` is required and MUST be in `1..100`. A response can contain fewer
   events only because fewer retained events satisfy the cursor; a Hub MUST NOT
   scan or replay unbounded history to fill a page.
3. Only a client with existing authorized `session:<id>:control` or
   `session:<id>:view` read authority may page that Session. Adapter tokens,
   `api:*`, and unauthorized group membership do not grant history paging.
4. The client MUST use `next_before_seq` unchanged for the next older page. It
   MUST NOT substitute `last_seq`, a timestamp, Task/Run identifiers, or local
   cache state.

The response contains the request and Session IDs, durable `events`,
`latest_seq`, `next_before_seq`, and `retention_state`:

```json
{
  "frame": "history.page",
  "request_id": "hist_01H8X",
  "session_id": "ses_01H8X",
  "events": [
    { "frame": "event", "type": "session.message", "seq": 52, "time": 1764937200123, "payload": {} },
    { "frame": "event", "type": "session.tool_call", "seq": 53, "time": 1764937201123, "payload": {} }
  ],
  "latest_seq": 57,
  "next_before_seq": 52,
  "retention_state": "complete"
}
```

Rules:

1. `events` contains durable event envelopes only, in strictly ascending `seq`
   order. Ephemeral events, heartbeats, cached rows, and synthetic sequence
   numbers never appear.
2. A non-null `next_before_seq` equals the smallest `seq` in this page and
   means earlier retained events exist. `null` means none remain. A client can
   call history complete only when `next_before_seq` is `null` and
   `retention_state` is `complete`.
3. `retention_state` is `complete` or `retention_gap`. `retention_gap` means
   at least one earlier durable range was pruned. It MUST be returned for both
   empty and non-empty pages and MUST render as an explicit gap, never an empty
   successful history.
4. A deleted, unauthorized, or temporarily unavailable Session returns
   `error(code=history_unavailable)` without an empty successful page.

The v2 EventStore interface adds `History` without changing forward replay:

```go
type HistoryPage struct {
    Events         []Event
    LatestSeq      int64
    NextBeforeSeq  *int64 // nil: no earlier retained event
    RetentionState string // "complete" | "retention_gap"
}

type EventStore interface {
    Append(ctx context.Context, sessionID string, evs []PendingEvent) (firstSeq int64, err error)
    Replay(ctx context.Context, sessionID string, afterSeq int64, fn func(Event) error) error
    History(ctx context.Context, sessionID string, beforeSeq *int64, limit int) (HistoryPage, error)
    LatestSeq(ctx context.Context, sessionID string) (int64, error)
}
```

## Attention Summary Subscription

`attention.subscribe` is a v2-only, capability-gated read of a bounded set of
provider-neutral Session summaries. It is not a Task/Run query, transcript
subscription, event replay, historical pagination, or adapter management path.
The Hub accepts Session IDs only and never reads deployment business tables.

Only a v2 `hello.ack` with
`capabilities.attention_summary: { "max_sessions": 64 }` permits the frames.
A v1 acknowledgement omits the capability and v1 frames receive
`error(code=attention_unsupported)`. An attention-scoped client uses a separate
connection and MUST NOT request ordinary `subscriptions` or `last_seq` replay.
Conversely, `control` and `view` do not imply attention access.

```json
{
  "frame": "attention.subscribe",
  "request_id": "attn_01H8X"
}
```

Rules:

1. `attention:<id>` is a short-lived, non-upgradeable client scope. Auth maps
   it to an opaque grant containing a canonical issuer-ordered Session
   allowlist, cap, and expiry. The Hub takes the first
   `min(grant.max_sessions, 64)` entries. Grant order is the sole
   inclusion/eviction tie-break: the Hub neither reads Task priority nor sorts
   or independently selects members. A duplicate, invalid, or empty allowlist,
   or a cap outside `1..64`, fails closed as detail-free
   `attention_unavailable`.
   `group:*`, `api:*`, `session:*:adapter`, `view`, and `control` cannot
   substitute for the grant.
2. A connection has at most one attention subscription. Every subscribe frame
   atomically rebuilds membership from the current grant's ordered prefix: the
   Hub swaps only after its new snapshot is readable and then emits it; failure
   clears membership and emits no partial result. Authorization change, expiry,
   identity change, or close removes membership. Reconnect starts empty and
   needs a current-identity subscribe frame and snapshot. The Hub uses shared
   per-Session fanout and MUST revalidate grant identity, expiry, revocation,
   and exact allowlist at membership replacement, snapshot read, and
   immediately before every update fanout. On failure it clears membership
   before sending, so no queued frame can disclose a summary.
3. The Hub uses shared per-Session
   fanout and MUST NOT allocate an unbounded goroutine, timer, queue, or scan
   per member or historical subscription.

The Hub returns the initial snapshot and subsequent changes as:

```json
{
  "frame": "attention.summary",
  "request_id": "attn_01H8X",
  "kind": "snapshot",
  "subscription_state": "complete",
  "summaries": [
    {
      "session_id": "ses_01H8X",
      "latest_seq": 57,
      "state": "waiting_permission",
      "permission": { "id": "pr_01H90", "status": "pending" },
      "terminal_outcome": null,
      "latest_change_seq": 55,
      "blocker": {
        "kind": "queued",
        "reason": "capacity",
        "expires_at": 1764937800000,
        "blocking_session_id": "ses_01H8Z"
      },
      "summary_version": 12,
      "summary_state": "complete"
    }
  ]
}
```

Rules:

1. `kind` is `snapshot` or `update`. A snapshot is emitted only after an
   authorized membership replacement or reconnect. An update contains only
   current members with any changed summary field. Event-backed field changes
   MUST emit an update even if `summary_version` did not change;
   `summary_version` identifies ledger-only evidence. Within a frame, summaries
   are sorted by `session_id`; their order never establishes cross-Session
   event or work order.
2. A summary contains only its Session ID, Hub-issued `latest_seq`,
   provider-neutral `state`, optional unresolved `permission={id,status}`,
   optional `terminal_outcome`,
   `latest_change_seq`, optional `blocker`, and monotonic per-Session
   `summary_version`. `permission.id` is an opaque existing permission request
   ID and `permission.status` is only `pending`; after resolution permission is
   null and no action, risk, detail, or provider object is exposed.
   `blocker.kind` is `queued`, `reauthorization_required`,
   `new_run_required`, or `outcome_unknown`; only `queued` can carry `reason`,
   `expires_at`, and `blocking_session_id`, and only `outcome_unknown` can
   carry a bounded `operation`. Summaries MUST NOT contain Task/Run IDs,
   transcript text, messages, tool output, file/diff data, credentials,
   provider objects, browser cache values, or synthetic sequence values.
3. `latest_seq` and `summary_version` are independent version domains. Clients
   use `latest_seq` only for durable-event evidence and `summary_version` only
   for ledger-only blocker/attachment/delivery evidence. Neither substitutes
   for the other, confirms transcript read, creates a global cursor, or changes
   replay/history/live-event behavior.
4. `subscription_state` and `summary_state` are `complete` or `incomplete`.
   A missing, stale, corrupt, incompatible, or unbuilt projection MUST be
   explicit `incomplete`, never a fabricated no-attention result. Only a
   snapshot with any current member `incomplete` MUST itself be `incomplete`.
   Only a
   separate checkpointed maintenance/backfill process may build summaries, in
   batches of at most 256 Sessions; subscription requests MUST NOT scan or
   rebuild full history.

The EventStore owns the durable projection. Event append and changes to
`latest_seq`, state, permission, terminal outcome, `latest_change_seq`, and
the original Store-clock `last_durable_event_at` commit in the same transaction.
An accepted client-command ledger mutation commits its original Store-clock
`last_client_command_at` and the new `summary_version` in its own transaction;
queued, reauthorization, new-run-required, and outcome-unknown ledger changes
likewise atomically commit their blocker and version. Ledger writes never
allocate, reuse, or replace durable event `seq`.

Ephemeral events, adapter heartbeats, supervisor liveness, dispatcher or
callback receipts, and retry cadence MUST NOT advance either timestamp, seq,
summary version, or blocker. After rollback, restart, concurrent writes, or
retention, the Store exposes one committed projection or `incomplete`; it never
fabricates idle or no-attention truth.

An attention scope can receive only the summary frames above. It cannot
subscribe to durable or ephemeral events, replay or page history, attach,
reauthorize or rotate an adapter, obtain credentials, send commands, answer
permissions, or mutate Session/summary state. Such frames fail their existing
authorization checks without changing a live subscription, ledger, or Store.

The v2 interfaces add the following contracts without changing the v1
EventStore interface:

```go
type AttentionBlocker struct {
    Kind              string // queued | reauthorization_required | new_run_required | outcome_unknown
    Reason            *string
    ExpiresAt         *time.Time
    BlockingSessionID *string
    Operation         *string
}

type AttentionPermission struct {
    ID     string // opaque permission request ID
    Status string // pending
}

type SessionAttentionSummary struct {
    SessionID           string
    LatestSeq           int64
    State               string
    Permission          *AttentionPermission
    TerminalOutcome     *string
    LatestChangeSeq     *int64
    Blocker             *AttentionBlocker
    SummaryVersion      int64
    LastDurableEventAt  *time.Time
    LastClientCommandAt *time.Time
    StateOfProjection   string // complete | incomplete
}

type AttentionGrant struct {
    SessionIDs  []string // Auth-supplied canonical order; Hub consumes its bounded prefix
    MaxSessions int
    ExpiresAt   time.Time
}

type AttentionSummaryStore interface {
    AttentionSnapshot(ctx context.Context, sessionIDs []string) ([]SessionAttentionSummary, error)
}

type AttentionAuthorizer interface {
    AuthorizeAttention(ctx context.Context, p Principal) (AttentionGrant, error)
}
```

## Ephemeral `x.vm.idle_warning`

v2 emits only the opaque platform extension:

```json
{
  "vm_id": "vm_01H8X...",
  "seconds_until_suspend": 600,
  "suspend_at": "2026-06-21T12:30:00Z",
  "message": "This VM will pause soon because it has been idle."
}
```

- `seconds_until_suspend` is non-negative at send time; `suspend_at` is RFC3339 UTC.
- The event omits `seq` and MUST NOT enter EventStore, replay, durable browser
  state, or durable analytics.
- The Hub receives a bounded injected version-to-opaque-type map. It selects by
  negotiated version only and MUST NOT hardcode the type, inspect `vm_id`, or
  infer VM lifecycle semantics.
- Durable `vm.idle_10m` notification/outbox delivery is unchanged and outside
  this protocol event stream.

## Legacy Window And Sunset

v1 `session.idle_warning` is supported through `2027-01-08T00:00:00Z`, 180
days after v2 spec approval. Before that timestamp v1 emits only the legacy
name and v2 emits only `x.vm.idle_warning`. T1B is the separate docs-only
removal contract. T15K and T52B remain time-gated until T69 and approved T1B.
