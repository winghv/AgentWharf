# AgentWharf Hub Protocol v1

## Status

This document is the authoritative frozen legacy v1 protocol specification for AgentWharf.
It defines the WebSocket protocol used by clients, adapters, and the Hub to
synchronize long-running agent sessions.

The protocol is provider-neutral and host-neutral. AgentWharf does not define
how a host is created, metered, or administered. Deployments can map their own
host concepts to AgentWharf sessions outside this protocol.

## Goals

1. Provide a durable per-session event stream with Hub-issued sequence numbers.
2. Support multiple clients observing and controlling the same session.
3. Allow clients and adapters to reconnect without losing durable events.
4. Keep provider-specific behavior out of the Hub by using adapters.
5. Keep self-hosting simple: one Hub process, one adapter process, and a local
   EventStore are enough for a complete setup.

## Non-Goals

1. Defining the provider-side agent protocol. Adapters should use ACP when a
   provider supports it and fallback transports only when needed.
2. Moving large file contents through WebSocket frames. Large blobs should use a
   separate content-addressed endpoint.
3. Multi-Hub coordination. v1 assumes one authoritative Hub per session.
4. End-to-end encryption. v1 relies on TLS, scoped tokens, and a trusted Hub.

## Roles

| Role | Responsibility |
| --- | --- |
| Hub | Authenticates connections, assigns durable event sequence numbers, persists durable events, fans out events, routes commands, and replays gaps. |
| Adapter | Bridges a provider process to the Hub protocol and reports provider activity as normalized session events. |
| Client | Subscribes to event streams and sends commands such as user messages, approval decisions, interrupts, and stop requests. |

Rules:

- The Hub never executes provider commands. Execution is adapter-side only.
- The adapter never talks directly to clients. All traffic goes through the Hub.
- Durable event `seq` values are assigned only by the Hub after persistence.

## Transport

Transport is WebSocket over TLS (`wss://`) with JSON text frames.

One connection has one role:

- A client connection can subscribe to one or more sessions.
- An adapter connection serves exactly one session.

Future binary encodings can be negotiated in a later protocol version.

## Frames

| Frame | Direction | Purpose |
| --- | --- | --- |
| `hello` | Peer -> Hub | First frame. Authenticates, declares role, negotiates protocol version, and optionally supplies replay cursors. |
| `hello.ack` | Hub -> peer | Accepts the connection and returns session summaries. |
| `event` | Adapter -> Hub, Hub -> clients | Session event. Durable events have `seq`; ephemeral events omit `seq`. |
| `event.receipt` | Hub -> Adapter | v2-only acknowledgement of one committed durable Adapter event proposal. |
| `command` | Client -> Hub -> adapter | Idempotent operation identified by `cmd_id`. |
| `command.ack` | Hop-by-hop | Acknowledges a command as `accepted`, `rejected`, or `duplicate`. |
| `ping` | Either direction | Heartbeat request. |
| `pong` | Either direction | Heartbeat response. |
| `error` | Hub -> peer | Protocol error with a machine-readable code. Fatal errors are followed by connection close. |

## Handshake

Client `hello`:

```json
{
  "frame": "hello",
  "protocol_version": 1,
  "role": "client",
  "token": "<scope-bound token>",
  "subscriptions": [
    { "session_id": "ses_01H8X", "last_seq": 41 }
  ]
}
```

Adapter `hello`:

```json
{
  "frame": "hello",
  "protocol_version": 1,
  "role": "adapter",
  "token": "<session-bound adapter token>",
  "session_id": "ses_01H8X",
  "provider": "claude-code",
  "resume": true
}
```

Client `hello.ack`:

```json
{
  "frame": "hello.ack",
  "protocol_version": 1,
  "sessions": [
    {
      "session_id": "ses_01H8X",
      "state": "ready",
      "provider": "claude-code",
      "latest_seq": 57,
      "replay_from": 42
    }
  ]
}
```

Version negotiation:

- Peers send the highest protocol version they support.
- The Hub selects the highest mutually supported version.
- If no mutually supported version exists, the Hub sends `error` and closes.

## Persistence And Replay Rules

These rules are normative:

```text
R1  seq is a per-session monotonically increasing integer starting at 1.
    The Hub assigns seq during durable event persistence.
R2  Durable events must be successfully appended to the EventStore before
    they are broadcast. If persistence fails, the event does not exist.
R3  Ephemeral events have no seq, are not persisted, are not replayed, and
    may be dropped without breaking protocol correctness.
R4  EventStore implementations must enforce UNIQUE(session_id, seq).
R5  Replay returns all durable events in (last_seq, latest_seq] ordered by
    seq, then continues with the live stream without gaps or duplicates.
```

Durable event envelope:

```json
{
  "frame": "event",
  "type": "session.message",
  "session_id": "ses_01H8X",
  "seq": 42,
  "time": 1764937200123,
  "payload": {}
}
```

Ephemeral event envelope:

```json
{
  "frame": "event",
  "type": "log.tail",
  "session_id": "ses_01H8X",
  "time": 1764937200123,
  "payload": {}
}
```

`time` is Unix time in milliseconds.

## Durable Events

| Type | Producer | Meaning |
| --- | --- | --- |
| `session.state` | Adapter or Hub | Session state transition. |
| `session.message` | Adapter or Hub | Conversation message. Hub records user messages before routing `session.send`. |
| `session.tool_call` | Adapter | Tool call start or result. |
| `permission.request` | Adapter | Provider asks for approval before an action. |
| `permission.decision` | Hub | User or policy decision for a permission request. |
| `file.changed` | Adapter | Workspace file change summary. Optional in the v1 minimum implementation. |
| `session.file_references.capabilities` | Adapter | v2 durable bounded file/image-reference capability. |
| `session.file_references.outcome` | Adapter or Hub | v2 durable reference delivery outcome with no path or bytes. |
| `session.error` | Adapter or Hub | Non-recoverable error detail. |
| `x.*` | Any peer allowed by policy | Extension namespace. The Hub persists and forwards durable extension events but does not interpret them. |

## Ephemeral Events

| Type | Producer | Meaning |
| --- | --- | --- |
| `agent.activity` | Adapter or Hub | Real-time activity summary. Not replayed. |
| `log.tail` | Adapter or Hub | Terminal or build log tail. Not replayed. |
| `session.idle_warning` | Hub | Deprecated legacy-only warning that the backing VM will soon be suspended for idleness. Not persisted or replayed. |

### `session.idle_warning` (deprecated legacy-only)

```json
{
  "vm_id": "vm_01H8X",
  "seconds_until_suspend": 600,
  "suspend_at": "2026-06-21T12:30:00Z",
  "message": "This VM will pause soon because it has been idle."
}
```

Fields:

- `seconds_until_suspend`: non-negative seconds from Hub send time to expected suspend time.
- `suspend_at`: RFC3339 UTC timestamp.
- The event is ephemeral: it has no `seq`, MUST NOT be written to EventStore,
  and is not replayed after reconnect.
- Durable platform notification delivery uses `vm.idle_10m`; it does not change
  Hub event sequencing.
- v1 emits only this legacy name. It MUST NOT emit `x.vm.idle_warning` on the
  same connection. The support window ends at `2027-01-08T00:00:00Z`; see v2.

### `session.message`

```json
{
  "message_id": "msg_01H8Y",
  "role": "user",
  "content": [
    { "kind": "text", "text": "Continue" },
    {
      "kind": "attachment",
      "blob": "sha256:ab12",
      "name": "mock.png",
      "media_type": "image/png"
    }
  ],
  "in_reply_to": "msg_01H8X"
}
```

Fields:

- `role`: `user`, `agent`, or `system`.
- `content`: ordered message parts.
- `in_reply_to`: optional message id.

### `session.tool_call`

```json
{
  "tool_call_id": "tc_01H8Z",
  "phase": "start",
  "name": "bash",
  "input": { "command": "npm install" },
  "result": null
}
```

Result example:

```json
{
  "tool_call_id": "tc_01H8Z",
  "phase": "result",
  "name": "bash",
  "input": null,
  "result": {
    "status": "ok",
    "output_preview": "added 1024 packages",
    "truncated": true
  }
}
```

Large outputs must be represented as previews plus optional blob references.
The maximum event payload size is 64 KiB.

ACP mapping rule:

- When an ACP provider exposes an action through `session/request_permission`
  without also sending an explicit `tool_call` or `tool_use` update, the adapter
  MUST first emit a durable synthetic `session.tool_call` with `phase=start`,
  then emit the existing `permission.request`.
- The synthetic `tool_call_id` MUST be stably derived from the permission
  request id. The recommended format is `permission:<request_id>`.
- The synthetic `name` is the ACP `action`, or `permission` when action is
  absent. The synthetic `input` contains the action, summary, risk level, and
  provider options when present.
- The subsequent `permission.request.detail` still carries provider options and
  provider session id for approval routing and audit.

### `permission.request`

```json
{
  "request_id": "pr_01H90",
  "action": "git.push",
  "risk_level": "medium",
  "summary": "Agent requests permission to push to origin/main",
  "detail": {},
  "expires_at": 1764937800000
}
```

Fields:

- `risk_level`: `low`, `medium`, or `high`.
- `expires_at`: Unix time in milliseconds.

### `permission.decision`

```json
{
  "request_id": "pr_01H90",
  "decision": "approve",
  "decided_by": "usr_01H91",
  "note": ""
}
```

Fields:

- `decision`: `approve`, `deny`, or `expired`.
- `decided_by`: user id or a policy actor such as `policy:auto`.

### `file.changed`

```json
{
  "paths": [
    { "path": "src/app.ts", "change": "modified" },
    { "path": "package-lock.json", "change": "modified" }
  ],
  "batch_id": "fc_01H92",
  "summary": { "modified": 2, "added": 0, "deleted": 0 }
}
```

`change` is `added`, `modified`, or `deleted`.

## Ephemeral Events

Ephemeral events omit `seq` and are never persisted.

| Type | Meaning |
| --- | --- |
| `presence` | Online clients and typing indicators. Optional in the v1 minimum implementation. |
| `agent.activity` | Transient provider activity such as thinking, tool execution, or a turn boundary. |
| `log.tail` | Terminal or build log tail. |
| `resource.sample` | Instantaneous resource sample. |

`agent.activity` uses provider-neutral `kind` values. Adapters SHOULD emit
`kind=turn_completed` as soon as a provider exposes an authoritative terminal
boundary for the current turn. The payload MAY include opaque `turn_id`,
`provider_session_id`, and `duration_ms` fields. Consumers MUST treat this as a
terminal activity hint for live rendering; because the event is ephemeral, they
MUST still reconstruct settled history from durable messages and tool results.

## Commands

Command envelope:

```json
{
  "frame": "command",
  "cmd_id": "cmd_01H91",
  "type": "session.send",
  "session_id": "ses_01H8X",
  "payload": {
    "content": [{ "kind": "text", "text": "Continue" }]
  }
}
```

| Type | Direction | Effect |
| --- | --- | --- |
| `session.send` | Client -> Adapter | Sends a user message. The Hub first persists a `session.message` with `role=user`, then routes the command. |
| `permission.respond` | Client -> Hub -> Adapter | Records and routes an approval decision. |
| `session.interrupt` | Client -> Adapter | Interrupts the provider's current action. |
| `session.stop` | Client -> Adapter | Ends the session and asks the provider process to exit gracefully. |

Command acknowledgement:

```json
{
  "frame": "command.ack",
  "cmd_id": "cmd_01H91",
  "status": "accepted",
  "reason": ""
}
```

Rules:

- `cmd_id` is generated by the sender and must be unique for the sender's
  command stream.
- The Hub returns `duplicate` for a previously accepted `cmd_id` and must not
  execute it again.
- `accepted` means the receiving hop accepted the command. Provider-visible
  results are reported later as events.
- When the adapter is offline, the Hub can buffer `session.send` and
  `permission.respond` for up to 64 commands or 10 minutes. Other commands are
  rejected with `adapter_offline`.

## Session File Reference Contract (T11A, v2)

This is a v2-only contract for referring to a published workspace file without
putting file bytes into Hub frames. It does not change legacy v1 `attachment`
blob semantics. A v1 connection MUST NOT advertise
`capabilities.file_references`, emit `session.file_references.capabilities` or
`session.file_references.outcome`, or send a `file_reference` content part. A
v1 attempt receives `command.ack(status=rejected,
reason=file_references_unsupported)` and creates no durable user message,
outbox record, Adapter delivery, or Provider operation.

### Capability Advertisement

Only a v2 `hello.ack` that advertises the exact object below enables the
grammar in this section:

```json
"file_references": {
  "schema_version": 1,
  "max_references": 8,
  "max_metadata_bytes": 8192
}
```

The authenticated Adapter MUST publish a durable
`session.file_references.capabilities` event on connect and whenever its
Provider capability changes. Its payload is an exact object with
`schema_version=1`, `fingerprint`, `max_references`, `max_total_bytes`, `file`,
and `image`. `max_references` is 1..8; `max_total_bytes` is 1..10485760. `file`
is the exact object `{mode,max_bytes,reason}`. `image` is the exact object
`{mode,max_bytes,media_types,reason}`. Every `reason` is either null or an
ASCII stable code matching `[a-z][a-z0-9_]{0,63}`.

For either `file` or `image`, `mode=allowed` requires `reason=null` and
`max_bytes` in 1..`max_total_bytes`; `mode=unsupported` requires a non-null
reason and `max_bytes=null`. An allowed image capability has 1..4 strictly
byte-sorted `media_types`, each one of `image/png`, `image/jpeg`, `image/webp`,
or `image/gif`; an unsupported image capability has `media_types=[]`. There is
no wildcard, SVG, HTML, XML, PDF, browser sniffing, or Provider-defined media
type escape hatch.

`fingerprint` is lowercase `sha256:<64 hex>` over this versioned
length-prefixed canonical encoding:

```text
utf8("agentwharf.file-reference-capability.v1") || 0x00 || u8(1) ||
u8(max_references) || u64be(max_total_bytes) ||
u8(file_mode == "allowed" ? 1 : 0) || u64be(file_max_bytes_or_zero) ||
u16be(len(file_reason_or_empty)) || utf8(file_reason_or_empty) ||
u8(image_mode == "allowed" ? 1 : 0) || u64be(image_max_bytes_or_zero) ||
u8(image_media_type_count) || each byte-sorted media type:
  u16be(len(media_type)) || utf8(media_type) ||
u16be(len(image_reason_or_empty)) || utf8(image_reason_or_empty)
```

Unknown, duplicate, missing, non-canonical, oversized, or fingerprint-mismatched
members are rejected before persistence. The capability payload contains no
Provider object, credential, Session content, host path, workspace bytes, or
tenant filename.

### `session.send` File References

When any `file_reference` occurs, the v2 `session.send` payload has the exact
members `content` and `capability_fingerprint`; the latter must equal the last
durably persisted capability fingerprint. Text-only sends retain their existing
payload shape. A `content` array carrying a `file_reference` contains only the
existing `{kind:"text"}` part and this exact reference part; it MUST NOT mix a
legacy `attachment` blob with file references:

```json
{
  "kind": "file_reference",
  "disposition": "file",
  "path": "src/app.ts",
  "version": "opaque-file-version",
  "content_digest": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "bytes": 123,
  "media_type": "text/plain"
}
```

`disposition` is exactly `file` or `image`. `path` is strict UTF-8, 1..1024
bytes, workspace-relative, uses `/`, has at most 32 non-empty segments, and
rejects leading slash, backslash, NUL, `.` and `..` segments. It never carries
`/workspace`, a host path, URL, URI, file descriptor, blob ID, or archive
entry. `version` is an opaque 1..256-byte value. `content_digest` is exactly
`sha256:<64 lowercase hex>`, `bytes` is an integer in 0..10485760, and
`media_type` is null or a 1..127-byte ASCII media type. The canonical UTF-8
JSON encoding of all reference parts is at most 8192 bytes; there are at most
eight references and their declared `bytes` sum is at most the advertised
`max_total_bytes`. `blob`, `base64`, `data`, `url`, `href`, inline text, and
unknown reference members are rejected.

The Hub checks only this bounded grammar, the current capability fingerprint,
reference count, and declared byte limits. It MUST NOT open a path, check file
existence, resolve a symlink, compare a digest, infer MIME, inspect bytes, or
interpret Provider behavior. A stale/missing/unsupported capability rejects the
command before a durable `session.message`; a changed file is not silently
accepted under an old fingerprint. `disposition=file` requires `file.mode` to
be allowed. `disposition=image` requires `image.mode` to be allowed and its
non-null media type to be one of the exact advertised image media types.

For every accepted file-reference send, the same EventStore transaction appends
the durable user `session.message` and creates one opaque
`FileReferenceCommandLedger` record containing only `session_id`, `cmd_id`,
Hub-created `message_id`, capability fingerprint, ordered reference count,
canonical request fingerprint, delivery writer tuple (null until routing), and
terminal status. The ledger never duplicates a path, filename, digest, byte
count, or file content.
The Hub adds that `message_id` only when forwarding the v2 command to the
authenticated Adapter; a Client-supplied forwarded message ID is rejected. At
delivery the Hub conditionally binds the current authenticated Adapter
connection epoch, credential generation, and writer lease to the ledger. Only
that current tuple may append its one terminal reference outcome, and only if
the persisted `session_id`, `cmd_id`, `message_id`, capability fingerprint, and
rejected reference index still match. The Hub rejects stale, duplicate, cross-Session,
unknown-command, or out-of-range outcome proposals without durable mutation.

After Hub persistence and routing, the Adapter revalidates every reference as
one all-or-nothing set in its own trusted workspace boundary: canonical relative
path, regular-file/no-follow containment, T11 publication/quarantine state,
current version, digest, byte count, media type, and current capability. Missing,
removed, stale, changed, quarantined, unsafe, over-limit, or unsupported-image
references cause zero references to reach the Provider; the Adapter never falls
back to a path string, stale bytes, MIME guess, or partial subset.

The Adapter emits exactly one durable `session.file_references.outcome` for the
ledger. It is `delivered` only after every reference has been revalidated and
crossed the Adapter-to-Provider input boundary; it is not a Provider work
success. It is `rejected` before any reference crosses that boundary. Hub
writer loss, disconnect, crash, restart, deadline, or an unconfirmed
Adapter-to-Provider handoff finalizes the ledger exactly once as
`outcome_unknown`; Hub never auto-replays a reference command, and the Client
must use a new `cmd_id` to try again. The rejection form is:

```json
{
  "message_id": "msg_01H8Y",
  "cmd_id": "cmd_01H91",
  "outcome": "rejected",
  "reference_index": 0,
  "reason": "stale_reference"
}
```

Every outcome has exact members `message_id`, `cmd_id`, `outcome`,
`reference_index`, and `reason`. `message_id` and `cmd_id` must match the
ledger. For `rejected`, `reference_index` is a zero-based index below the
persisted reference count and `reason` is exactly one of `missing`, `removed`,
`stale_reference`, `size_changed`, `media_type_changed`, `image_unsupported`,
`provider_unsupported`, `unsafe_path`, `quarantined`, or `access_denied`. For
`delivered`, both `reference_index` and `reason` are null. For
`outcome_unknown`, `reference_index` is null and `reason` is exactly
`delivery_unconfirmed`, `writer_lost`, or `adapter_deadline`. It contains no
path, filename, digest, byte count, or content. Hub persists and fans out this
bounded outcome but does not interpret `delivered` as a Provider
success/failure. Provider execution after a delivered reference set retains the
ordinary `session.send` outcome semantics.

No raw file or image bytes enter a command, event, EventStore, replay,
transcript, outbox, ActivitySink, audit metadata, metrics, ordinary log, or
Client cache through this contract. Bytes reach a Provider only through the
Adapter after the all-or-nothing revalidation above. Retried `cmd_id` values
retain normal duplicate semantics and never re-open or re-deliver a reference.

## Permission Flow

```text
provider attempts an action
  -> adapter emits a synthetic session.tool_call(phase=start) when the ACP
     request has no explicit tool_call/tool_use update
  -> adapter pauses the provider and emits permission.request
  -> Hub persists the request and broadcasts it
  -> a client sends permission.respond
  -> Hub persists permission.decision and broadcasts it
  -> Hub routes the decision to the adapter
  -> adapter resumes or denies the provider action
```

Rules:

- Only the first valid decision for a `request_id` is accepted.
- Later responses for the same `request_id` return `duplicate`.
- Policy decisions are also persisted as `permission.decision`.
- If a request expires, the Hub persists `decision=expired`; adapters must
  treat expiration as denial.

## Reconnect And Replay

Client reconnect:

```text
client hello includes last_seq
  -> Hub replays durable events in (last_seq, latest_seq]
  -> Hub switches the connection to the live stream
```

Adapter reconnect:

```text
adapter hello includes resume=true
  -> Hub verifies the session binding
  -> Hub accepts the adapter
  -> Hub delivers buffered commands in order
```

If the adapter process restarts with the provider process, recovery is
provider-specific. The adapter should emit `session.state` transitions such as
`recovering -> ready` or `ended` with a crash reason.

## Adapter Session State

Legal state transitions:

```text
starting -> ready
ready -> busy
busy -> ready
busy -> waiting_permission
waiting_permission -> busy
waiting_permission -> ready
ready -> recovering
busy -> recovering
recovering -> ready
any -> ended
any -> error
```

Common `ended.reason` values:

- `user_stop`
- `provider_exit`
- `crash`
- `timeout`

Adapters must:

- Prefer ACP for provider integration.
- Keep provider-specific parsing in provider-specific adapter packages.
- Supervise provider process lifetime with bounded restart attempts.
- Send `ping` every 20 seconds and treat 60 seconds without heartbeat as
  offline.
- Apply secret masking before sending user-visible text to the Hub.
- Reduce a workspace directory to its final path segment before it enters
  `session.state` metadata. `metadata.cwd` is OPTIONAL, and when present it MUST
  be a bare directory name: no absolute or relative path, no separator, no
  ancestor segment. An adapter that cannot reduce the value safely MUST omit the
  key rather than send a path. `session.state` is durable, so an absolute path
  would disclose the host account name and directory layout to every later
  reader and replay. The unreduced path may still reach the provider through a
  local provider-protocol request that does not enter the EventStore.

## Operational Diagnostics

This section is a deployment safety requirement and does not add a v1 frame,
scope, token, or wire behavior. Prometheus metrics use only bounded labels such
as module, role, protocol version, operation class, outcome, reason class, and
finite state. They MUST NOT label by account, organization, host, session,
request/job/credential identifier, Provider object, path, raw error, or user
content. Structured operator logs may use authorized opaque correlation keys,
but never bearer values, secrets, profile bytes, or user content.

Hub diagnostics bind only to a controlled loopback or authenticated internal
operator path. An Adapter sharing a sandbox with an untrusted Provider MUST NOT
open TCP or loopback metrics/pprof. It may expose standard read-only handlers
only through a protected fixed-entry-owned Unix socket whose path, mount, UID,
peer credential, and inherited FDs are inaccessible to the Provider. If that
proof, listener rate/concurrency bound, or shutdown cleanup cannot be made, the
Adapter diagnostics listener MUST remain disabled; it MUST NOT fall back to a
Provider-reachable endpoint. Profile output is restricted operational data and
MUST NOT enter protocol events, EventStore, transcripts, audit metadata,
ordinary logs, or Provider-readable storage.

Diagnostics have no queue: one socket admits at most two connections and four
requests per rolling minute; only `GET`/`HEAD` with no body and at most 8 KiB
headers are accepted, responses are capped at 16 MiB, and CPU/trace accepts
only `seconds=1..30` with one shared active-profile slot. Excess requests get a
detail-free `429` only when safe to write, otherwise the connection closes.
Shutdown stops accepts, cancels work, closes connections, and removes the
socket within five seconds. An implementation MUST NOT create an unbounded
goroutine, queue, buffer, or per-peer map to enforce these bounds.

## Scope And Authorization

Tokens are issued outside the Hub. The Hub authenticates tokens and authorizes
requested scopes.

| Scope | Capability | Typical holder |
| --- | --- | --- |
| `session:<id>:control` | Subscribe and send all session commands. | Interactive client. |
| `session:<id>:view` | Subscribe only. | Read-only client. |
| `session:<id>:adapter` | Connect as the adapter for one session. | Adapter process. |
| `group:<id>:control` | Control all sessions in a group. | Multi-session client. |
| `api:*` | Programmatic full access. | Administrative integration. |

Rules:

- Adapter tokens and client tokens are not interchangeable.
- Adapter tokens are bound to one session.
- The protocol only knows sessions and optional groups. Deployments map their
  own host and account concepts externally.

## Hub Embedding Interfaces

Go implementations should expose interfaces equivalent to:

```go
type PendingEvent struct {
    Type    string
    Time    time.Time
    Payload json.RawMessage
}

type Event struct {
    SessionID string
    Seq       int64
    Type      string
    Time      time.Time
    Payload   json.RawMessage
}

type EventStore interface {
    Append(ctx context.Context, sessionID string, evs []PendingEvent) (firstSeq int64, err error)
    Replay(ctx context.Context, sessionID string, afterSeq int64, fn func(Event) error) error
    LatestSeq(ctx context.Context, sessionID string) (int64, error)
}

type Authenticator interface {
    Authenticate(ctx context.Context, token string) (Principal, error)
    Authorize(ctx context.Context, p Principal, scope Scope) error
}
```

`Append` must allocate contiguous sequence numbers atomically for all events in
the batch.

## Protocol Evolution

- `protocol_version` is an integer.
- Within v1, implementations may add event types and optional fields.
- Within v1, implementations must not change existing field semantics or remove
  fields.
- Clients must ignore unknown event types.
- The `x.*` namespace is reserved for deployment-specific extensions. The Hub
  stores and forwards durable extension events without interpreting them.
- A v2 Adapter proposes every durable `event` with a `proposal_id`: an opaque
  UTF-8 value of 1 through 255 bytes. `proposal_id` is not a command ID,
  operation ID, credential, grant, Provider object, or event payload field.
  The Adapter reuses the exact ID only to retry the exact same durable event
  after a lost acknowledgement. A v2 durable event supplies a positive Unix
  millisecond `time`; the Hub does not assign or normalize that time. A
  missing, empty, oversized, duplicate JSON member, Client-supplied value,
  absent or nonpositive durable-event time, or value on an ephemeral event is
  rejected without a Store write, broadcast, activity observation, or receipt.
- The Hub synchronously asks its `ProposedEventStore` to commit a v2 proposal
  under the current authenticated Adapter authority tuple. The Store assigns
  the authoritative durable sequence and deduplicates only the exact same
  `(session_id, proposal_id, type, time, payload)` retry. A changed retry or
  stale/revoked/expired/replaced/terminal writer is rejected and creates no
  durable event. After an accepted commit, the Hub sends this exact Adapter-only
  frame before live fanout:

  ```json
  {
    "frame": "event.receipt",
    "proposal_id": "proposal_01H8X",
    "seq": 42,
    "status": "accepted"
  }
  ```

  The receipt has exactly these four members. It is reference-only, is never
  persisted or replayed, and never carries event content, a session identifier,
  grant, bearer, credential, or Provider data. Receipt-write failure does not
  undo an accepted Store commit: the Hub still fans out the committed sequence,
  and the Adapter retries its same proposal ID to recover the authoritative
  receipt. Per-Session durable publication serializes proposal commit/receipt/
  fanout with Client durable command publication and retained v1 Adapter batch
  append/fanout, preserving one live sequence order.
- v1 is frozen for durable proposal receipts: a v1 Adapter omits `proposal_id`,
  receives no `event.receipt`, and keeps the existing batched durable-event
  path. A Client must never send `event` or receive `event.receipt`; a v1
  Adapter `proposal_id` and any inbound `event.receipt` are protocol errors.
- v1 is frozen for the v2 Session Settings Capability Contract: it MUST NOT
  advertise `capabilities.settings` or emit `session.settings.capabilities` or
  `session.settings.effective`. A v1 `session.settings.change` command receives
  `command.ack(status=rejected, reason=settings_unsupported)` and creates no
  durable event, pending state, or Provider operation.
- v1 is likewise frozen for v2 run-control completion negotiation: it MUST NOT
  advertise `capabilities.run_control` or emit `session.run.capabilities` or
  `session.run.outcome`. Its existing `session.interrupt` and `session.stop`
  commands retain their legacy routing-ack semantics. A v1 attempt to use the
  v2 run-control capability/outcome frames receives `error(code=run_control_unsupported)`
  without durable mutation.
- v1 is frozen for v2 file references: it MUST NOT advertise
  `capabilities.file_references`, emit `session.file_references.capabilities` or
  `session.file_references.outcome`, or accept a `file_reference` content part.
  Such a send receives `command.ack(status=rejected,
  reason=file_references_unsupported)` without durable mutation.

## Security

- The Hub has no command execution side effects.
- Tokens should be short-lived and scoped to the minimum required capability.
- User-visible text sent by adapters should pass through secret masking.
- The Hub and EventStore must not receive known plaintext secrets from adapter
  output.
- Blob endpoints must be content-addressed and scope-checked.
- Self-hosted default listeners should bind to localhost unless explicitly
  configured otherwise.
- v1 assumes a trusted Hub. Deployments requiring an untrusted Hub need a future
  end-to-end encryption extension.

## Minimum v1 Implementation

Required for v1:

- Frames: `hello`, `hello.ack`, `event`, `command`, `command.ack`, `ping`,
  `pong`, and `error`.
- Durable events: `session.state`, `session.message`, `session.tool_call`,
  `permission.request`, `permission.decision`, and `session.error`.
- Ephemeral events: `agent.activity`, `log.tail`, and
  `session.idle_warning`.
- Commands: `session.send`, `permission.respond`, `session.interrupt`, and
  `session.stop`.
- Replay, command idempotency, adapter heartbeat, and adapter recovery states.
- EventStore and Authenticator interfaces.
- A local EventStore implementation and one adapter path.

Deferred from the minimum:

- `file.changed`.
- `presence`.
- Blob endpoint.
- Additional provider-specific fallback adapters.
- Alternate binary frame encoding.
- End-to-end encryption extension.
